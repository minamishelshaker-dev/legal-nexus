## Source review

### Implemented paths/components found

- Bilingual public landing page (Arabic / English).
- Email/password signup and login forms.
- Supabase Auth callback route supporting PKCE code exchange and OTP token hashes.
- Session-aware middleware for workspace and onboarding routes.
- First-organization onboarding. A database trigger adds the creator as organization owner.
- Organization structure: corporate entities and departments.
- Legal matters and contract record creation/listing.
- Legal request intake/listing.
- Administrative investigation intake and a multi-tab case-detail interface for sessions, statements, evidence, minutes, recommendations, decisions and appeals.
- Private investigation evidence upload flow records SHA-256 and custody events through a database RPC.

### Known limitations / follow-up work

1. **Authentication acceptance test is outstanding.** The signup callback is hardcoded to the production hostname. This is acceptable for the canonical production host but means preview deployments will not automatically receive their own callback URL. Keep Supabase Site URL set to the canonical production domain and explicitly allow the production callback URL. Add local/preview redirect patterns only if those environments are intended to be used.
2. Test signup confirmation end-to-end, including the exact link generated by the configured Supabase email template, callback exchange, profile upsert and redirect to onboarding.
3. Test first-organization creation and verify the database trigger creates exactly one active owner membership.
4. Add and test password reset, resend-confirmation, and a clear recovery path for expired confirmation links.
5. Add user/member administration and invitation acceptance/revocation UI. Database RPCs exist, but their end-to-end UI path was not established in this review.
6. Add edit/detail screens for contracts and legal matters; current `CoreRecords` component primarily creates and lists records.
7. Complete legal-request review, assignment, comments and approval actions in the UI; current `LegalRequests` component primarily submits and lists requests.
8. Complete full role-matrix testing for owner, admin, legal manager, lawyer, HR investigator and ordinary member. Verify cross-organization isolation using two independent test organizations.
9. Verify investigation state transitions and all evidence/minutes/recommendation/decision/appeal flows with real authenticated users, including denied actions.
10. Review the deployment's environment variables and Supabase Auth URL configuration in their dashboards. Values/secrets were not read or changed during this audit.

## Manual acceptance checklist

- [ ] Signup with a new test email.
- [ ] Confirm email link opens the canonical production callback, not localhost.
- [ ] Callback establishes a session and creates/updates the user profile.
- [ ] First login redirects to onboarding.
- [ ] Creating an organization creates the creator's owner membership.
- [ ] Logout and login work reliably.
- [ ] Second user can join only via a valid invitation.
- [ ] Owner/admin/legal manager permissions match the intended matrix.
- [ ] Ordinary member cannot access restricted HR/investigation records.
- [ ] Cross-organization reads and writes are denied.
- [ ] Contracts, matters and legal requests can be created and then correctly retrieved.
- [ ] Investigation evidence upload, download-link audit, SHA-256 and review events work.
- [ ] Submitted investigation minutes cannot be silently edited.
- [ ] No secrets or service-role keys are exposed to the browser.

## Release decision

**Not yet acceptance-tested as a complete MVP.** The production infrastructure and security baseline are present, but a live user acceptance pass and completion of the workflow gaps above are required before presenting the system as fully operational. Do not seed fake customer records in the production database for testing.
